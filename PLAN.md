# PLAN — subwatch

Local-first трекер підписок: без хмари, без акаунтів, без доступу до банку.

## 1. Цільова аудиторія

- **Первинна:** "privacy-conscious" користувачі (40–55, технічно грамотні),
  які вже самохостять щось (Home Assistant, Nextcloud) і НЕ віддадуть
  банківські дані хмарному трекеру типу Rocket Money заради контролю
  підписок. Мають 10–30 активних підписок.
- **Вторинна:** фрілансери/ Solo-SaaS — бізнес-підписки (CI, хостинг,
  SaaS-інструменти), де списання йдуть з різних карток і валют, і
  підзвітність (звіт "скільки я плачу на місяць за інструменти") критична.
- **Третинна:** сім'ї — один член сім'ї веде список сімейних підписок
  (стрімінги, хмарні сховища, ігрові сервіси).

## 2. Проблема / Evidence

- **42%** забувають про платну підписку (Capterra) — тобто майже кожен
  другий платить за те, чим не користується.
- **$17/міс** (~$204/рік) — середня втрата на невикористаних підписках
  (CNET, 2025).
- **44%** мають subscription fatigue — втому від кількості й непрозорості
  списань.
- **+6%/рік** — зростання одноразових покупок як реакція на підписочну
  втому: ринок рухається ВІД підписок, але існуючі підписки нікуди не дінуться
  — керування ними залишається проблемою.
- Конкуренти (Rocket Money, Truebill) — cloud-only, вимагають банківський
  доступ, беруть % "заощаджень". Ніша local-first безпечного трекера порожня.

## 3. MVP scope (реалізовано)

- Python FastAPI + SQLite (stdlib sqlite3) + мінімальний UI без build-степу.
- Модель Subscription: name, amount, currency, cycle (monthly/yearly/custom),
  custom_days, anchor_day (month-end якір), next_due_date, trial_end_date,
  notes, tags, active.
- Функції:
  - список підписок з сортуванням по next_due_date (також amount/monthly/name);
  - monthly-equivalent total (per currency) + річний перерахунок;
  - календар майбутніх списань на 30/60/90 днів (`/api/upcoming?days=N`);
  - reminders: локальний CLI `python -m backend.remind` (друк + опційна
    локальна Windows-нотифікація) — без хмарних пушів;
  - .ics export всіх наступних списань (RFC 5545, CRLF, ескейпінг);
  - триал-трекер: попередження за 3 дні до кінця trial (`/api/trials`,
    червоний рядок у UI, окрема подія TRIAL END в .ics);
  - mark-paid: перекрутити next_due_date на цикл вперед.
- Тести: pytest на month-end edge cases (31 січня + 1 місяць, високосний
  рік), monthly-equivalent, ICS-структуру/ескейпінг/UID, CRUD API.

## 4. Архітектура

```
backend/
  db.py        sqlite3-схема: subscriptions (одна таблиця — навмисно)
  schedule.py  чисті функції: add_months/add_years з anchor_day,
               next_due_date, nth_occurrence, monthly_equivalent,
               upcoming_dates, trial_ending_soon
  ics.py       RFC 5545 генерація (CRLF, escaping, стабільні UID)
  main.py      FastAPI: CRUD + summary/upcoming/trials/export.ics + static
  remind.py    CLI: друк майбутніх списань, опційна локальна нотифікація
static/index.html  UI без build-степу
```

Важливі рішення:
- **anchor_day** зберігається в БД при створенні: день місяця, до якого
  "прив'язана" підписка. Без нього ланцюжок Jan 31 → Feb 28 → Mar 28
  дрейфує; з якором — Mar 31. Це головна пастка календарної математики.
- **custom цикл** у днях: weekly = custom_days=7. Monthly-equivalent
  рахується через 365.25/days — дає 4.33-week months чесно.
- **Один SQLite-файл** = переносимість: скопіював файл — переніс усе.

## 5. Roadmap

### MVP (поточний коміт)
CRUD, сортування, monthly-equivalent, календар 30/60/90, CLI-reminders,
.ics export, триал-трекер, тести.

### v1 — "щоденний драйвер"
- Багатовалютність: конвертація через ECB у базову валюту для summary.
- Імпорт: парсинг виписок CSV (детекція повторюваних списань як підписок).
- Деферри: pause/skip циклу, "cancel reminder" за N днів ДО списання
  (щоб встигнути скасувати, а не дізнатись постфактум).
- Docker-упаковка, автозапуск remind через планувальник (schtasks/cron).

### v1.5 — "аналітика"
- Історія зміни ціни підписки (Netflix підняв ціну — графік).
- Категорії/теги з агрегацією, спільні сімейні підписки (split по людях).
- Cost-per-use: ручне позначення використання → вартість одного сеансу.

### v2 — "продукт"
- PWA + локальні веб-пуші (service worker, без сервера).
- One-time purchases tracker (тренд +6%/рік): амортизація покупки по місяцях.
- Синхронізація між пристроями БЕЗ хмари: Syncthing-сумісний SQLite
  (litestream/cr-sqlite) — опційно.

## 6. Монетизація (one-time / freemium self-hosted)

- **Core — безкоштовно назавжди** (MIT, self-hosted, один користувач).
- **Pro — one-time $19:** імпорт виписок з авто-детекцією підписок,
  cost-per-use, історія цін, priority support.
- **Family — one-time $29:** multi-profile у тому самому файлі, спліт
  сімейних підписок.
- Свідомо БЕЗ підписки на продукт трекера підписок — це суперечило б
  самому продукту і було б ідеальним маркетинговим фейлом.

## 7. Ризики

| Ризик | Імовірність | Мітигація |
|---|---|---|
| Календарні edge cases (month-end, DST не стосується дат) | середня | anchor_day +pytest на всіх краях; pure-функції легко фуззити |
| Користувач забуває запускати remind | висока | .ics export — нагадування живуть у календарі, який людина вже відкриває щодня |
| "Ще один трекер" — ніша здається зайнятою | середня | позиціонування local-first/no-bank-access — унікальне проти Rocket Money |
| Ціни підписок змінюються непомітно | низька | v1.5 історія цін + diff при mark-paid |
| SQLite-конкурентний доступ | низька | single-user сценарій, WAL |

## 8. Free-tier джерела даних

Підписки не потребують зовнішніх даних взагалі (сума/дата вводяться
користувачем або з CSV-виписки) — тому проект повністю offline. Для v1
імпорту виписок: експорт CSV з банку користувача (локальний файл, без
банківських API). Курси валют для багатовалютного summary v1:
ECB eurofxref-daily.xml (безкоштовно, без ключа).
